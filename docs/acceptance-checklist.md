# DeskWeek 验收清单

日期：2026-11-10。适用：Windows 电脑 + Android 手机 + Android 平板。

这份清单告诉你**怎么测试 DeskWeek 的各项功能**，以及每一项的通过标准。当前能测的主要是本地任务和小组件；三端自动同步等功能还在开发中，对应步骤暂时标"阻塞"。

## 1. 开发团队需要先准备什么

在你开始测试之前，下面这些东西应该由开发团队提供好：

| 要测的功能 | 开发团队先做好 | 你什么时候可以开始测 |
| --- | --- | --- |
| 三端任务同步 | 把 Windows 和 Android 的同步模块写完，并让任务库和日志对接好 | 在手机上新建一条任务，另一台设备能看到 |
| 自动连接 | 配对流程、设备列表、自动发现和重连 | 重启 App 后不用重新填地址 |
| 冲突处理和移除设备 | 冲突查看和选择界面、设备移除功能 | 能在界面上操作，不只是看日志 |
| 后台同步 | 符合系统限制的后台调度 | 先把前台同步测通，再测后台 |
| 更多日历视图 / AI 附件 | 对应的功能和测试材料 | 功能做好后再测 |
| 升级测试 | 旧版和新版测试包、模拟升级的环境 | 在测试目录里验证，不需要发布正式版 |

开发团队还需要提供：版本号和提交标识、APK 校验值、测试用的 150 条任务文件、日志导出方式、自动化测试结果等。

## 2. 你需要准备什么

- 一台 Windows 电脑、一部 Android 手机、一台 Android 平板（品牌不限，记下型号和系统版本就行）
- 一台路由器，三台设备能互相访问（先关掉手机和平板的移动数据，确保走的是局域网）
- 如果有 Wallpaper Engine 安卓版，准备一张动态壁纸用来做兼容性测试
- USB 线（方便装包和查日志）
- **用测试数据来测！** Android 装 DeskWeek Debug 版，电脑用单独的测试目录。开始前先备份你的日常数据，别在真实数据上做删除或覆盖测试。

> 测试时先用普通家庭网络（不要用访客网络），确保设备之间能互相访问。Windows 防火墙只需要允许测试程序通信就行，不用关掉整个防火墙。

## 3. 结果怎么记

每一项只能填下面五种结果之一：

| 结果 | 意思 |
| --- | --- |
| 通过 | 测了，结果符合预期，有截图或日志为证 |
| 失败 | 功能已经做了，但结果不对 |
| 阻塞 | 功能还没做完或缺少测试条件，暂时测不了 |
| 未覆盖 | 缺对应的设备或系统，没法测（比如没有某个 ROM 的手机） |
| 延期 | 计划中的后续功能，不能写成"通过" |

**性能参考值**（在权限都开好、配对完成后）：
- 发现已配对设备：10 秒内
- 已连接时，少量修改传到对面：5 秒内
- 断网恢复后，重新发现加交换：15 秒内

核心功能至少做 3 轮测试。没通过的要记下实测数值，不能为了通过随意放宽标准。

## 4. 按顺序测试核心功能

### A. 首次配对与自动发现

1. 三台设备都连上路由器，打开 App，进入同一个测试数据组
2. 逐对配对：电脑↔手机、电脑↔平板、手机↔平板，核对双方显示的设备名和验证码
3. 退出三个 App 再重新打开，**不用重新输入地址**
4. 检查设备列表、连接状态、上次同步成功的时间

**通过标准**：三对关系都建立了；重启后自动找到对方并连接。没有配对的设备只能被发现，看不到任务。拒绝权限后本地功能仍然可用，同时告诉你为什么连不上。

### B. 三端任务双向同步

分 6 个方向测试：电脑→手机、手机→电脑、电脑→平板、平板→电脑、手机→平板、平板→手机。

每个方向都做：

1. 在普通任务页面新建一条任务（比如 `测试_手机_第1轮`），填上备注、日期和时间
2. 确认另一台设备的 App 和桌面小组件都显示了这条任务
3. 改标题和日期，勾选完成，再取消完成
4. 删到垃圾箱，再恢复
5. 退出两端 App 重新打开，检查数据还在

**通过标准**：所有内容和状态一致，没有重复也没有丢失。已连接时 5 秒内同步完成。

另外：关掉电脑，只用手机和平板测试双向同步（不要用电脑热点做网络，否则电脑关了网也断了）。

### C. 断网编辑后重新汇合

1. 三台设备先同步好同一条任务，然后分别断网
2. 每台各新建 3 条不同任务；电脑改旧任务标题，手机改日期，平板完成另一条
3. 恢复网络，保持三台都在前台，等数据汇合
4. 重新打开各端，逐条比对

**通过标准**：新建的 9 条都在，旧任务的标题、日期和完成状态也都对。恢复后 15 秒内完成同步。

### D. 同时修改和删除

| 场景 | 操作 | 正确结果 |
| --- | --- | --- |
| 同一个字段被两端改了 | 同步好一条任务后，电脑和手机断网，分别把标题改成不同内容，再联网 | 界面显示两个候选版本，你选一个后三端统一 |
| 一边删一边改 | 电脑断网后删除任务，手机断网后改了它的备注，再联网 | 任务在垃圾箱里，恢复后备注还在 |
| 永久删除 | 平板离线保留旧数据；电脑彻底删除并同步手机，然后平板联网 | 三端都删干净了，重启也不会复活 |

### E. 大量数据、断线恢复和文件导入导出

1. 用测试文件（150 条任务）从 App 的导入入口导入一端，再同步三端
2. 同步中途断一次 Wi-Fi，恢复后继续
3. 三端各导出 data.json 并对比
4. 升级测试包，重启，检查数据和小组件
5. 分别测试合并导入和覆盖导入

**通过标准**：150 条完整无缺无重复；断线后能补齐；覆盖导入后，被删的任务不会被其他端的旧数据带回来。

### F. 各种网络环境

| 场景 | 操作 | 正确结果 |
| --- | --- | --- |
| 没有外网 | 路由器开着但断了宽带，手机关掉移动数据 | 局域网同步正常，AI 等联网功能不影响本地任务 |
| 换了 IP 地址 | 重新连 Wi-Fi 或路由器重新分配地址 | 不用重新配对，自动重连并补齐数据 |
| 换了网络 | 三台设备一起换到另一个网络 | 原来的配对仍然有效 |
| 设备隔离 | 如果路由器支持，开启访客隔离 | 显示"无法连接"，恢复后自动补齐 |

### G. 移除设备后重新加入

1. 手机和平板各自移除对电脑的信任
2. 两台 Android 新建任务，电脑也新建任务并尝试连接
3. 确认被移除的电脑收不到新任务，电脑的修改也传不到 Android
4. 重新配对后恢复同步

## 5. 后台和续航测试

先把上面 A～G 都测通，再做这部分。

| 场景 | 操作 | 怎么判断 |
| --- | --- | --- |
| 切到后台 | Android 按 Home 键回到桌面，电脑改任务，分别在 15/30/60 分钟后查看 | 记下实际延迟，没有同步记录的写"待观察" |
| 锁屏放置 | 手机不充电放 30～60 分钟，期间其他端改任务 | 解锁打开 App 后自动补齐，没丢也没重复 |
| 强行停止 | 在系统设置里强行停止 App，其他端继续改 | 重新打开后能恢复并补齐 |
| 重启手机 | 重启后观察 | 数据和配对信息都还在 |

> 后台同步的"自动"是指系统允许 App 运行时才会同步。如果需要"锁屏后立即同步"的效果，需要额外实现并验证，当前不承诺。

**续航测试建议**：同一台手机，先关闭同步静放 8 小时作基线，再开启同步静放 8 小时，记录起止电量，至少做两轮。

## 6. 壁纸兼容与显示测试

| 项目 | 操作 | 通过标准 |
| --- | --- | --- |
| Wallpaper Engine | 开着动态壁纸，添加 DeskWeek 小组件 | 壁纸继续动，没有被 DeskWeek 接管；文字可读 |
| 换壁纸/换页/锁屏 | 换壁纸、翻桌面页、锁屏解锁、重启 | 小组件正常，任务没丢 |
| 大/中/小尺寸 | 三种尺寸各试一次（10 条任务） | 不重叠、不缩到看不见，超出的有"还有 N 项"提示 |
| 横竖屏和分屏 | 手机和平板都试横竖屏、分屏 | 不遮挡，按钮都能点到 |
| 大字号 | 把系统字号调到最大 | 能滚动到所有内容和按钮 |
| 无障碍 (TalkBack) | 开启 TalkBack 后操作一遍：新建、编辑、完成、删除、翻周 | 控件能朗读、可操作、焦点顺序合理 |

> 没装 Wallpaper Engine 就跳过 WE 兼容项，只测普通壁纸下的小组件。不要在这里启用 DeskWeek 的实验动态壁纸，那是另一种模式。

## 7. 其他功能的测试方法

| 功能 | 怎么测 |
| --- | --- |
| 年/月/日视图 | 同一组任务在各视图切换并编辑，检查跨年、大小月、闰日 |
| 农历/节气/调休 | 和日历或官方放假通知对比 |
| AI 附件/OCR | 每种支持的格式（文本、PDF、图片等）用已知内容的文件测试 |
| AI 逐条选择 | 生成 3 条任务后只选第 1 和第 3 条，确认只添加了选中的 |

## 8. Windows 测试

- **窗口可见性**：连续用 24 小时，包括锁屏、睡眠、全屏游戏等。如果浮窗消失了，记下什么时候消失的、当时在做什么。
- **更新检查**：
  1. 点"检查更新"能正常返回结果
  2. 在测试环境里模拟一次完整的下载→校验→更新→重启流程

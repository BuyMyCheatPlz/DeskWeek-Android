# JSON 二维码离线传输方案

2026-11-10 更新：本方案替代了之前的局域网自动同步。两台设备面对面就能传任务，不需要同一 Wi-Fi、不需要服务器、不需要账号、不需要联网。传递的是当前任务的一次性快照，接收后由你确认导入。

## 怎么用

| 方向 | 发送端操作 | 接收端操作 |
| --- | --- | --- |
| 电脑 → 手机/平板 | 管理中心 → 设置 → 离线传输与备份 → 生成二维码 | 设置 → 扫描二维码 → 收齐 → 合并或替换 |
| 手机/平板 → 电脑（文件） | 设置 → 导出 data.json，通过 USB 拷到电脑 | 管理中心 → 设置 → 导入 JSON → 合并或替换 |
| 手机/平板 → 电脑（扫码） | 设置 → 展示二维码 | 管理中心 → 设置 → 摄像头扫码导入 |
| 手机 ↔ 平板 | 设置 → 展示二维码 | 设置 → 扫描二维码 |

电脑端可以选择摄像头、重新打开相机、清空已扫描的进度。Android 只在进入扫描页面时才申请相机权限，拒绝权限不影响本地任务和文件导入。关闭扫码页面后相机会停止。画面在本机处理，不上传。

## 数据规则

- 二维码直接承载 JSON 数据本身，不包含网址，不指向服务器
- 数据量小的时候一张二维码就够了（上限约 650 字节）
- 数据量大时自动分成多张，每张约 300 字节，包含批次编号、序号和校验码
- 可以乱序扫、重复扫，同一张只算一次。缺张、混入其他批次、校验不过的都不会写入
- 二维码生成后就是固定快照；之后再改了任务需要重新生成。超过 20 张会建议改用文件传输
- 二维码是明文的，只能保证数据完整，不能证明发送者身份——请面对面核对
- 传输的内容包括：任务 ID、标题、备注、日期/时间、提前显示设置、完成状态和垃圾箱状态。API 密钥不参与传输

**合并**：保留你手机上的其他任务，同一个 ID 的任务用导入内容覆盖（包括完成和删除状态），不会产生重复任务。你的个人设置不受影响。

**替换**：用导入的任务列表完全替换当前所有任务。操作前会提示你确认。

> 永久删除过的任务不会出现在快照里。合并不会自动推断删除——如果需要和发送端完全一致，请选择替换。旧快照也可能覆盖你的新修改，导入前请确认来源和时间。

## 怎么测试

先备份日常数据，使用最新的电脑程序和 Android Debug 测试包。

1. **断网扫码**：关掉 Wi-Fi 和移动数据，电脑新建一条包含中文和表情的任务，生成二维码。手机先取消确认数据没变，再重新扫码并合并
2. **多张收集**：让数据足够多以生成至少 3 张。先扫最后一张，再重复扫第一张，确认进度不重复计数。缺一张时不能导入，补齐后合并
3. **混批与坏码**：收集 A 的一张后修改数据生成 B，扫 B 时提示是另一份数据。非二维码或乱码图案报错，本机任务不变
4. **合并语义**：接收端有自己的任务，导入后独立任务保留，同 ID 的任务更新为导入内容
5. **替换和持久化**：替换后只剩发送端的任务。退出重开 App，结果不变
6. **文件回传**：在 Android 修改任务后导出 data.json，通过 USB 传到电脑导入
7. **电脑摄像头回传**：Android 展示二维码，电脑用摄像头扫描导入
8. **权限和界面**：拒绝相机权限后仍可管理任务和文件导入。横竖屏、进度显示正常
9. **边界情况**：空列表、超大文件提示改用文件、不兼容的格式版本拒绝导入

手机和平板分别执行。只有真实设备通过光学扫描才能标记硬件验收通过。

# 功能验证与修复报告

> 2026-11-11：小组件新增任务后仍为空的问题已复现并修复，见 [本次排查与回归记录](widget-refresh-fix.md)。以下为此前版本的历史验证记录。

日期：2026-11-10。本轮基于 Android `4456a59`（版本号 1.2.0）与 Windows `9782379`，对已有功能进行检查和修复。没有升级版本号，没有提交、推送或发布。

## 概要

对本地任务管理、文件导入导出、AI 文本提取、同步协议核心组件、桌面小组件和 Windows 浮窗进行了全面回归测试。**三端任务的自动同步仍未打通，还不能算完成。** 同步实验界面已标注为"独立日志实验"以避免误导。

## 修复了什么

| 问题类别 | 原来的问题 | 修复内容 |
| --- | --- | --- |
| 导入校验 | 空 JSON `{}` 能清空全部任务，重复 ID 被随机改写 | 现在要求有效的任务列表，拒绝重复 ID，无效导入不影响现有数据 |
| 文件损坏恢复 | 主文件和备份都坏了还能保存为空 | 现在拒绝空数据写入，需要用有效数据重新导入才能恢复 |
| 兼容性 | 不认识的字段保存后丢失 | 现在会保留额外字段，编辑和导出后都不丢 |
| 版本号 | 导入旧文件会回退版本计数器 | 只增不减，不受导入文件影响 |
| 同时操作 | 多个地方同时新建任务会丢数据 | 改为排队处理，不再丢任务 |
| 编辑冲突 | 旧的编辑内容可能覆盖期间的修改 | 按字段合并，冲突时拒绝覆盖 |
| 分色/日期 | 新任务重启后日期变了，颜色分配受删除影响 | 保存前统一格式，颜色按固定规则分配 |
| 同步存储 | 日志损坏时静默清空，写入失败时仍然确认成功 | 完整校验数据，磁盘写入成功后才确认 |
| 跨作者因果 | 只等自己的操作序号，忽略了对方的操作依赖 | 现在等所有依赖都满足后才应用 |
| 合并逻辑 | 收到操作的顺序影响最终结果 | 改为确定性合并，无论顺序结果一致 |
| 网络安全 | 拉取操作不验证签名，不检查所属组 | 现在验证组、身份、签名和消息格式 |
| 小组件 | 只显示标题前两个字，编辑后不刷新 | 完整显示标题，修改后自动刷新 |
| 透明与日期 | 没有真正的透明设置，日期永远不更新 | 增加透明和文字颜色开关，定时刷新日期 |
| AI 解析 | 异常数据导致崩溃 | 过滤无效数据，错误时给出可读提示 |
| AI 密钥 | 密钥明文保存和显示 | 改为加密存储（Keystore），界面不显示明文 |
| Windows 取色 | 截屏错误时自动主题失败 | 增加备用取色方案 |
